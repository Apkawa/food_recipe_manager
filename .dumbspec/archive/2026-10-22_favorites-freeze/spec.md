# 2026-10-22_favorites-freeze: зависание при открытии рецепта из избранного

**Created:** 2026-10-22T11:37:59+03:00

## Scope

В scope:
- Баг: на продакшене (https://apkawa.github.io/food_recipe_manager/master/) браузер зависает при клике на рецепт из списка избранного.
- Воспроизводимый сценарий (из draft):
  1. Добавить рецепт «Тест» (ингредиенты «для пиццы 275 г», «соль 15 штук», «Рецепт на 4 порций»), добавить в избранное.
  2. Изменить текст рецепта на «Другой Тест» (ингредиент «Пиво 10л», «Рецепт на 4 порций»), снова добавить в избранное.
  3. В избранном 2 рецепта; клик по «Тест» — зависание.
- Установить, **почему баг не воспроизводится локально в dev**, а в проде — да.
- Найти корневую причину (root cause) и исправить / дать воспроизводимый способ.

Out of scope:
- Рефакторинг, не относящийся к багу.
- Изменение UX избранного.

## Approach

Research показал ключевую структуру:

- В **текущем** коде (master `1f7a270`) бесконечного цикла не найдено: парсинг мемоизирован по `rawRecipe`, цепочка state→URL→`applyFromQuery` сходится, парсер на обоих текстах отчёта завершается (проверено эмпирически).
- Структурная разница dev/prod: **PWA service worker в проде пре-кэширует JS-бандлы** (`vite.config.ts`: `autoUpdate` + `globPatterns` на js/css), а в dev — только статические ассеты. Браузер с устаревшим SW продолжает получать **старый бандл**.
- На master 2026-10-21 (за день до ветки задачи) упали два фикса избранного: `f7aabc4` (broken fav links) и `a2e429e` (open recipe from favorites). Старый бандл исполняет старый (сломанный) флоу избранного.

План действий (детали — в `plan.md`):
1. **Воспроизвести и доказать root cause** (глубокое расследование):
   - Собрать текущий master (production build), прогнать сценарий из draft через Playwright → убедиться, что в актуальном коде зависания **нет**.
   - Собрать кандидатские исторические версии (до `a2e429e` / до `f7aabc4` / одна более ранняя) и прогнать тот же сценарий → найти версию, которая **зависает**.
   - Локализовать бесконечный цикл в старой версии (консоль/стек/CPU).
2. **Фикс** — по итогам root cause:
   - Если цикл живёт в старом коде и уже исправлен в master: сделать так, чтобы пользовательский браузер гарантированно получал свежий бандл (SW-стратегия / принудительное обновление при обнаружении новой версии), т.к. сам «зависший» код исправить ретроспективно нельзя.
   - Если в актуальном production-сборке цикл всё же есть — исправить его.
3. **Проверка:** production-сборка + сценарий из draft (Playwright); по возможности — проверка на реальном URL проде.

## Constraints

- Стек: React 19 + Vite SPA (PWA, Workbox), Zustand, React Router (hash), pnpm workspaces; core — чистый TS, без UI.
- Деплой: GitHub Pages, ветка `master` → `https://apkawa.github.io/food_recipe_manager/master/`, `clean: true`.
- PWA: `registerType: "autoUpdate"`; prod пре-кэширует `**/*.{js,css,html,ico,png,svg}`; dev — только статику из `dev-dist/`.
- Избранное хранит **снимки** рецептов в `localStorage['recipe-favorite']` (plain JSON array).
- Core мутирует Recipe in-place (известная проблема).
- Footer `BuildInfo` показывает закоммиченный hash — по нему можно узнать, какой именно бандл отрисовывает зависший браузер.
